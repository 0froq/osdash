# Drop KV Implementation Plan

**Goal:** Stop using Cloudflare KV. Unread follows the GitHub notification inbox. Stars, later, and server-stored BYOK go away.

**Architecture:** The Worker keeps calling GitHub with the token in the encrypted session cookie, so a sleeping device still refreshes the board. Unread is the set of unread notification threads, matched to a card by `repo#number`. Marking a card read patches those threads. BYOK stays in `localStorage` and is sent only on the inbox request that needs it. OAuth state is always the signed payload that already exists. Cache API keeps the disposable GitHub responses. Notes stay on the paired device. The KV binding is removed only after nothing reads it.

**Tech Stack:** Existing Nuxt server routes, Vitest via `vp run test`, GitHub REST notifications. No new dependency. No UI tests.

**Out of scope:** Deleting the Cloudflare namespace from the dashboard. Leaving the binding unused is the code change. Wiping the namespace is a separate manual step. Do not add `repo` scope. Do not store a reaction, a star, or a snooze.

## Decisions

- Unread means GitHub says the thread is unread. The local `baselineAt` stamp goes away. A card with several members is unread when any member has an unread thread. `fixedBy` is not a member and does not affect unread.
- The inbox response carries the thread ids needed to mark those threads read. That id is a GitHub handle, not a preference we invented.
- First login shows GitHub's current unread set. We do not mark everything read to imitate the old baseline.
- `GET /notifications?participating=true&all=false` is the unread list. Paginate with `per_page=50` until a short page. Cache that list in the Cache API for 2 minutes under `notifications:v1:{login}`. `?refresh=1` skips that cache.
- Mark read is `PATCH /notifications/threads/{id}` for each id on the card. Then drop those ids from the cached unread list.
- OAuth authorize scope becomes `read:user notifications`. Existing sessions keep the old token until the user signs in again. A 403 or 404 on the notifications list means the token lacks the scope: the board still loads, every card is read, and the client shows that sign-in is out of date.
- BYOK is `{ baseUrl, apiKey, model }` in `localStorage` under `osdash.byok`. The inbox request sends it in `X-Osdash-Byok` as base64url JSON. The Worker uses it for that request and does not write it to Cache API, logs, or KV.
- Cloud notes in `prefs.notes` are abandoned. Device notes stay.

## Tasks

1. Add a pure notification match in `shared/notifications.ts`. Parse a notification `subject.url` into `{ repo, number, threadId }`. Build the unread set. Given a unit's members, return whether it is unread and which thread ids belong to it. Test a card that matches one of two threads, a card that matches none, a malformed url, and a card whose only hit is `fixedBy`. Run `vp run test`.

2. Fetch that list from the inbox load in `server/github.ts` or a new `server/notifications.ts`. Use the session token. On success, set `unread` from the match and attach `notificationThreadIds`. On a missing scope, set `unread` false, leave the ids empty, and add `notificationsScope: false` on the inbox payload. Cache the raw unread set in Cache API for 2 minutes. Do not call `readSeen`. Cover the scope failure and a cache hit with a fake `fetch` in a server test.

3. Replace `POST /api/seen` with a mark-read route that patches each thread id and updates the cached unread set. The client `markRead` keeps the optimistic unread clear. Remove `seen:v1` reads and writes from `server/user-state.ts`. Delete the seen tests that expect a baseline stamp. Keyboard `e` still marks read.

4. Remove stars and later. Delete the starred and later views, sidebar counts, card menu rows, shortcuts `s` and `l`, `utils/later.ts`, and the `star` and `later` branches of `POST /api/prefs`. `placeUnit` only returns `mine`, `waiting`, `ended`, or `hidden`. Drop `starred`, `laterUntil`, and the later count from `UnitView` and `inboxCounts`. Update `shared` and server tests that construct those fields.

5. Remove cloud notes from prefs. Device note routes stay. The preview reads notes only from the device. Delete prefs note create, move, and delete on `POST /api/prefs`. If that route no longer has a caller, delete it and `usePrefs`.

6. Move BYOK to the browser. Settings load and save `localStorage` only. `useInbox` attaches `X-Osdash-Byok` when a key is present. `loadInboxUnits` reads that header instead of `readByok`. Reject a header larger than 8 KB. Tests check that a supplied key is used for clef and that nothing calls `writeByok`. Delete the KV functions in `server/byok.ts`.

7. Delete the legacy OAuth KV path. `resolveOAuthStart` always returns a signed state, including when `OAUTH_CALLBACK_ORIGIN` is unset. The callback verifies the signature and does not call `readCache` for `oauth:v1`. Update `server/auth` tests. Production and local keep their own callback URL.

8. Remove the KV binding after `rg CACHE` no longer finds a runtime read or write. Edit `void.config.ts`, `cloudflare.config.ts`, and the local `kv_namespaces` entry in `nuxt.config.ts`. Leave `void.lock.json` for the deploy tool to rewrite. Do not call the Cloudflare API to delete namespace `370a971225924c648b29ccb32e7ae57f`. Update `README.md` and the data section of `AGENTS.md`.

9. Run `vp run check` and `vp run test`. Do not add UI tests. Do not deploy in this plan.

## User-visible behavior to check by hand

- Sign in again. GitHub asks for notification access. The board loads before that grant, with nothing marked unread.
- A card is unread only when GitHub's participating inbox has that issue or PR. Marking it read clears it here and on github.com.
- Star, later, and their pages and shortcuts are gone.
- Old cloud notes are gone. Device notes still load when Mini is online, and the board still refreshes when it is not.
- A BYOK key saved in one browser is absent in another. Clearing site data removes it.
- No request in this flow reads or writes the `CACHE` KV binding.
